# Behavioral: technical leadership — STAR outline

**Prompt:** “Tell me about a time you led a technical initiative without formal authority.”

## Probes

- Influence across teams?
- Tradeoffs communicated to non-engineers?
- Senior/staff signal

## Strong STAR skeleton

| Part | Content |
| --- | --- |
| **Situation** | Cross-team pain (tech debt, reliability, velocity) |
| **Task** | You volunteered to drive proposal — not assigned manager |
| **Action** | RFC doc → pilot → metrics → rollout plan → mentoring |
| **Result** | Team adoption, measurable improvement |

## Action bullets (template)

- Wrote RFC with problem, options, recommendation
- Ran 2-week pilot with one willing team
- Presented data to leadership (before/after metrics)
- Paired with 2 engineers on migration pattern
- Documented playbook in wiki/runbook

## Metrics examples

- Deploy frequency up, incident count down
- Build time −40%, dev NPS improved
- 3 teams adopted shared library

## Level calibration

| Level | Emphasis |
| --- | --- |
| Mid | Drove feature or component across one team boundary |
| Senior | Multi-team initiative with conflict resolution |
| Staff | Org-wide standard, executive alignment |

## Weak vs strong

| Weak | Strong |
| --- | --- |
| “I told them what to do” | RFC + pilot + adoption |
| Title-based authority | Influence via data |
