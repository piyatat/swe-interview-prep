# SWE resume

Goal: one page (two only if staff+/deep history) that proves **scope, impact, and fit** for a target role/level in ~6–8 seconds of skim.

## Structure

1. **Header** — name, location (or remote), email, LinkedIn/GitHub, portfolio if relevant  
2. **Title line** — target role + 1 specialty (e.g. “Backend Engineer — distributed systems”)  
3. **Experience** — reverse chronological; 3–5 bullets per recent role  
4. **Projects** (optional) — 1–2 if they show skills jobs don’t  
5. **Skills** — concise stacks you can defend in interview  
6. **Education** — short; omit GPA unless early-career and strong  

## Bullet formula

**Action + system/context + constraint + measurable result**

| Weak | Stronger |
| --- | --- |
| Worked on payments API | Led redesign of payments webhook path; cut p99 latency 40% under 2× traffic |
| Improved CI | Reduced CI wall time 18 → 7 min by sharding tests and caching deps |

Prefer **owned outcomes** over “helped with.” Quantify users, latency, cost, reliability, or cycle time when honest.

## Level signals on the page

| Level | Resume should show |
| --- | --- |
| Mid | Solid delivery in a team; clear tech ownership of features |
| Senior | End-to-end ownership; mentorship; tradeoffs; cross-team impact |
| Staff+ | Multi-team / org leverage; strategy; ambiguous problem framing |

See [leveling.md](leveling.md).

## ATS and skim pitfalls

- Prefer standard section headings; avoid text-in-images and heavy columns  
- Mirror **keywords** from the job post only where true  
- Drop ancient tech stacks that dilute the story  
- One consistent tense; past for previous roles  
- No confidential customer names or unreleased product details  

## Checklist before apply

- [ ] Top third sells the target role without reading bullets  
- [ ] Every recent bullet has impact or a crisp technical claim  
- [ ] Skills match what you’ll defend live  
- [ ] Links work; PDF/plaintext both readable
