# Applied Intuition engineering track

Sits beside [waymo.md](waymo.md) and [tesla.md](tesla.md): **physical AI tooling / autonomy OS** for automotive, trucking, defense, and industrial machines — not a consumer robotaxi loop and not Tesla Autopilot. Official [Careers](https://www.appliedintuition.com/careers): **build physical AI that moves the world**; ~1,000 engineers plus ex-CTOs / founders across cars, mining trucks, and fighter jets. Official [Hiring engineers for the age of agents](https://www.appliedintuition.com/engineering-blog/hiring-engineers-age-of-agents) (Jul 2026) is the process source of truth. Recruiter confirms **sim / maps / vehicle OS vs onboard autonomy vs defense**, language, Sunnyvale (or other office) **five-day in-person**, and whether *your* loop uses the new AI onsite.

Typical timeline **~3–6 weeks** once moving (official blog + new-grad brief). Coding: [../general/coding-patterns.md](../general/coding-patterns.md). AI-collaborative hour: [../general/ai-assisted-rounds.md](../general/ai-assisted-rounds.md). Sim / fleet cousin: [../answers/system-design-metrics.md](../answers/system-design-metrics.md). ## Official hire bar (do not invent extra pillars)

Official careers + [age-of-agents blog](https://www.appliedintuition.com/engineering-blog/hiring-engineers-age-of-agents) + [new-grad SWE brief](https://resource.applied.co/one-pagers/new-grad-swe). Map **your** stories.

| Official signal | What they score |
| --- | --- |
| **Physical AI that moves the world** (careers) | Safer machines / customer impact — not “I like self-driving cars” |
| **AI fluency is one aspect** (blog) | Decision-making, technical excellence, culture; AI is the **medium** |
| **Accountable for every line** (blog) | Phone screen is **no-AI** so they know you can read the code you ship |
| **Work the way we do** (blog) | Reject people who would be unhappy with agentic, in-office craft |
| **Hero project** (new-grad brief) | Early ownership of a customer-facing slice, not a toy intern app |
| **In-person five days** (new-grad brief) | Self-selects; flexibility for appointments / illness, not a remote loop |

“Why Applied?” that only says “AV / sim / Waymo energy” fails. Name a **simulation, map, vehicle-OS, or customer-integration** problem you have lived.

## Official + reported process

Official [age-of-agents](https://www.appliedintuition.com/engineering-blog/hiring-engineers-age-of-agents) publishes the 2026 SWE skeleton. Treat team variants as **recruiter-confirmed**.

| Stage | Official |
| --- | --- |
| Recruiter / leads chat | Fit; product area; in-person expectation; AI policy on *this* req |
| Technical phone (~45 min) | **No-AI** coding — baseline: you understand code without an assistant |
| Onsite design (~45 min) | Open-ended problem **usually from real Applied work** |
| Onsite build (~2 h) | Working prototype of that design — **any model, any frameworks** |
| Panel demo | What you built, decisions, what you would do differently |
| Offer | New-grad: team allocated in-loop, finalized later (brief) |

Official trial (30+ onsites): interviewers rated practical skills, unfamiliar challenges, technical communication, logical thinking, and mastery highly; **code elegance** stayed on the **phone screen**. Confirm whether your org has fully rolled the format out.

## How this track differs

| vs Waymo / Tesla | vs FAANG web |
| --- | --- |
| Official **split**: no-AI phone, then AI-native build + demo | Design is **sim / maps / vehicle OS / AEB**, not “design Twitter” |
| Customer-facing product engineers; Waymo is Alphabet Driver | Two-hour prototype is the **job**, not a hidden take-home |
| Five-day office; hero project in first months | Recruiter already probes “why physical AI, not a lab” |

## Coding and design flavor

Phone: medium DSA you can narrate without a model — graphs, geometry, intervals. Onsite: talk a **real** autonomy-tool problem, then ship a thin vertical slice (API + viz + a failing test you can defend). Related: [../general/take-homes.md](../general/take-homes.md), [../answers/coding-course-schedule.md](../answers/coding-course-schedule.md).

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** stack (ADP / maps / SDS / defense) — portable “I want AV” is weak.
2. Phone: medium with edges named; no assistant, no silent typing.
3. Design then build: offline eval or map-edit pipeline — what you cut to demo in two hours.
4. Demo: a decision the model suggested that you **rejected**, and why.
5. Questions for them: which office, hero-project examples, AI-in-pad on the phone.
