# Wayfair engineering track

Sits beside [etsy.md](etsy.md) and [walmart.md](walmart.md): **home-goods e-commerce SWE (Boston / …)**, not a unique-inventory craft loop and not a grocery / pickup retail hour. Official [SWE interview process](https://www.aboutwayfair.com/careers/tech-blog/commencing-your-technology-journey-at-wayfair-the-interview-process-for-software-engineers) (Mike Isman): **real problems, no tricks**; Google syntax if you need it; pick **your** language. Recruiter confirms **level**, whether the **phone screen** runs, virtual vs office panel, and AI (ask — the blog does not publish a live-AI rule).

Typical official path: **recruiter → technical screen → optional phone → onsite / virtual panel → internal review → fit & sell**. Culture: [../general/behavioral.md](../general/behavioral.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official culture (People Principles)

Do **not** invent Amazon-style LPs. Official [How we work](https://www.aboutwayfair.com/careers/how-we-work) anchors on **Great People / Great Ideas / Great Ambition**, then ten People Principles. The SWE blog maps the **four panel hours** onto three shorthand pillars: **We Drive Results**, **We Are Always Improving**, **We Win Together**.

| Official principle | What they score |
| --- | --- |
| **Relentless customer focus** | Exceptional home-shopper experience; everyone is in customer service |
| **Deliver results with agility** | Long-term value + urgency; learn from failure; measurable outcomes |
| **Use good judgement** | Bold, not reckless; data + pattern recognition |
| **Build the best team** | High bar, clear goals, hard people calls |
| **Collaborate effectively** | Cross-functional; disagree, align, commit |
| **Respect others** | Empathy; presume good intent; candor with humility |
| **Be an owner** | Wayfair-first; spend as if it is yours; think long-term |
| **Innovate & improve** | Challenge precedent; incremental **and** breakthrough |
| **Adapt & grow** | Self-reflection; opportunity in change |
| **A more equitable workplace** | DEI programs, not a slogan |

“Why Wayfair?” that only says “e-comm / Boston” fails — name a **catalog, fulfillment, or conversion** problem you have lived.

## Official process

Official [SWE interview process](https://www.aboutwayfair.com/careers/tech-blog/commencing-your-technology-journey-at-wayfair-the-interview-process-for-software-engineers). Interviewers train to a **rubric**; they write feedback **before** the panel debrief.

| Stage | Official |
| --- | --- |
| Recruiter call | Business + open roles; they match you; **ask questions** |
| Technical screen | Engineer-led coding **and** scale / capacity / networking / components; some roles use a **case** instead |
| Phone screen (level-dependent) | Impact + STAR on your work; technical decisions |
| Onsite / virtual panel | Four sessions on Google Meet or in a tech office |
| Internal review | Independent written feedback, then a panel decision; recruiter in a few days |
| Fit & sell | After offer details: HM session(s) so **you** confirm the team |

Official panel hours:

| Hour | Official score |
| --- | --- |
| Coding + Drive Results | HackerRank playground; **style, comprehension, speed, tests, communication**; working suboptimal beats a unfinished “perfect” |
| App architecture / data modeling + Always Improving | Logical design; in ~45 min deep-dive **two of** API / classes / schema, still **touch** all three |
| System design + Drive Results | Full-stack physical architecture: requirements, components, protocols, capacity, **ops / analytics** |
| Team building / leadership + Win Together | Project with business context + measured impact; hard relationship; compromise. Managers add career-dev / underperformance |

Official coding tips: name **time complexity**; break into functions; ask when stuck — they score coaching.

## How this track differs

| vs Etsy / Walmart | vs FAANG |
| --- | --- |
| Official **four-hour** panel + **fit & sell after** the offer | People Principles, not Leadership Principles |
| Dedicated **API / class / schema** hour | Home catalog + logistics, not “design Twitter” |
| Rubric + written feedback before debrief | “I only grind Blind 75 silently” misses architecture + STAR |

## Coding and design flavor

Official: CS fundamentals (structures, time/space) plus **Wayfair scale — millions of users**. Live: HackerRank, your language, tests as you iterate. Design: catalog search, cart / checkout, warehouse allocation, what you monitor when conversion drops. Related: [../answers/system-design-search.md](../answers/system-design-search.md), [../general/low-level-design.md](../general/low-level-design.md).

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** Wayfair surface (browse, cart, fulfillment, supplier) — portable “I like e-comm” is weak.
2. Coding: working code + tests + complexity; take a hint.
3. Architecture: APIs, classes, and a schema for a slice of checkout or catalog.
4. Design: where the bottleneck is at millions of shoppers; how ops sees it.
5. STAR vs **Win Together** or **Always Improving**.
