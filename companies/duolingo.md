# Duolingo engineering track

Sits beside [spotify.md](spotify.md) and [product-companies.md](product-companies.md): **consumer learning + experiments**, not a generic FAANG slate. Official [engineering interview guide](https://blog.duolingo.com/interviewing-with-duolingos-engineering-team/): recruiters **read every resume**; process is **pre-onsite + virtual onsite** (can split across days); **each role has its own plan**. Official [Engineering careers](https://careers.duolingo.com/engineering): **Learners first**; thousands of A/B tests a year; Engineering is about **half the company**. Recruiter confirms **backend vs iOS vs Android vs web**, which official interview **types** you get, and **AI policy**.

Typical timeline **3–5 weeks** (2026 guides). Pair: [../general/pair-programming.md](../general/pair-programming.md). Review: [../general/code-review-rounds.md](../general/code-review-rounds.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official operating principles (do not invent extra pillars)

Official [12 operating principles](https://blog.duolingo.com/operating-principles/) (2023). The [Handbook](https://handbook.duolingo.com/) later spotlights five stories (**Take the Long View, Raise the Bar, Ship It!, Show Don’t Tell, Make It Fun**). Use the **published names**; map your stories.

| Official principle | What they score |
| --- | --- |
| **Learners first** | Mission: best education, universally available; learner experience over vanity metrics |
| **Prioritize ruthlessly** | Data + experiments choose; kill what does not work |
| **Take the long view** | Short-term revenue that hurts learners is a no (official paywall example) |
| **Test it first** | Ship behind tests; intent + measurement |
| **Reduce complexity** | Simple internal comms and product |
| **Ship it** | Pragmatic excellence over ideological perfection |
| **Strive for excellence** | Bar plus trust; not heroics-as-culture |
| **Be candid and kind** | Transparency; assume good intent |
| **Explain why** | Task ↔ strategy |
| **Embrace challenges** | Setbacks → learning, not blame theater |
| **Never settle on talent** | Kindness + collaboration + growth, not only raw skill |
| **All for One, and One for All** | Accessible education as the shared goal |

“Why Duolingo?” that only says “I like the owl” fails. Name a **lesson, streak, experiment, or notification** problem you have lived.

## Official interview types

From the engineering blog — these are **types**, not a promise you get all of them.

| Official type | Time | What they score |
| --- | --- | --- |
| **Online coding task** | ≤60 min | University / new-grad only; auto-graded accuracy + time |
| **Technical video (CodeSignal)** | 60 min | Live algorithmic task with an engineer |
| **Pair programming** | 75 min | Production-like repo; work with **others’** code; learn on your feet |
| **Code review (CodeSignal)** | 60 min | Issues + improvements; specialized Backend / iOS / Android |
| **Whiteboard** | 60 min | University / new-grad; pseudocode OK; communication of the approach |
| **Design** | 60 min | Industry Backend / iOS / Android / Web; **approach**, not one solution. Mobile = architecture, not HLD boxes |

Accepted languages (official table): Python, Java, JavaScript, Kotlin, Swift — pair/review default to **Python or Java** on backend (they help with language details). Official prep: think out loud, **pragmatic** first solution, work **with** the interviewer (they hint), clarify, edges. All questions are sized to the slot.

## Official + reported process

| Stage | Official / reported |
| --- | --- |
| Recruiter | Human résumé read; they share **your** interview plan |
| Pre-onsite | Some mix of OA (new-grad), CodeSignal video, or a first pair |
| Virtual onsite | Multiple types above; may be **two+ days** |
| Close | Offer; Handbook: Luis and Severin still **approve every hire** — treat kindness as a bar |

Guides (Dataford, ClavePrep, 2026): ~4 rounds, 3–5 weeks. Confirm whether you get pair **and** review (common industry) vs OA + whiteboard (common university).

## How this track differs

| vs Spotify / consumer | vs FAANG |
| --- | --- |
| Official **published type list** + CodeSignal pair/review | Pair is **75 min in a repo**, not only a named LC |
| Design is **lessons / experiments / notifications**, or mobile architecture | New-grad **whiteboard + OA** are explicit |
| Kindness is a **hire bar** (Handbook airport-driver story) | “I only grind LeetCode” misses pair + review |

## Coding and design flavor

Live DSA is standard structures + big-O (official). Pair/review: read a foreign codebase, name a defect, ship a small change, stay kind. Design: experiment assignment, streak / lesson sequencing, notification volume without spam, or client architecture. Related: [../answers/system-design-notification.md](../answers/system-design-notification.md), [../general/code-review-rounds.md](../general/code-review-rounds.md).

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** surface (iOS / Android / lesson engine / growth) — “education is good” is weak.
2. Pair: make the suite green without rewriting the repo’s contract.
3. Review: one defect, one design note, one kind nit.
4. Design: pick the next lesson / notification — what you A/B, what you refuse to ship.
5. Principles: long-view vs ship-it tension you actually lived.
