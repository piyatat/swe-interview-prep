# Big tech vs startup — comparison

Use this to calibrate prep when applying to both types in parallel.

| Aspect | FAANG / big tech | Startup (Seed–Series C) |
| --- | --- | --- |
| **Timeline** | 4–8 weeks | 1–3 weeks |
| **Rounds** | 5–7 standardized | 3–5, varies by team |
| **Coding** | LeetCode-style, timed, rubric | Take-home, pair programming, domain bugs |
| **System design** | Abstract scale (100M+ DAU) | Pragmatic (10K now → 100K in a year) |
| **Behavioral** | STAR, LPs, bar raiser / HC | Founder fit, ownership, ambiguity |
| **Decision** | Committee, bar raiser veto | HM / founder, often same day |
| **AI tools** | Mixed — ask recruiter; some AI-free rounds | Often more practical + AI-tolerant |
| **Over-engineering** | Expected to discuss scale | **Penalized** — ship with 5 engineers |

## Prep time allocation

### Big tech (weekly)

| Block | Hours | Focus |
| --- | --- | --- |
| 40% | DSA timed | Medium/hard patterns, narration |
| 25% | System design | Classic prompts + estimations |
| 25% | Behavioral | 15–20 STAR stories (Amazon: LP-mapped) |
| 10% | Company research | Values, leveling, team match |

### Startup (weekly)

| Block | Hours | Focus |
| --- | --- | --- |
| 35% | Practical coding | Feature slice, refactor, tests |
| 25% | Product/architecture | Their stack, monolith-first design |
| 25% | Portfolio + take-home | One polished repo story |
| 15% | Culture / motivation | Why this stage, why this problem |

## Story tone

| Big tech | Startup |
| --- | --- |
| Repeatable execution at scale | Figuring it out without a playbook |
| Cross-functional process | Moving idea → action fast |
| Quantified impact at org level | Shipping with constraints |
| Risk awareness in large systems | Ownership with incomplete info |

## Red flags by context

| Context | Red flag |
| --- | --- |
| Big tech SDI | Jumping to microservices without requirements |
| Startup SDI | Kubernetes + 12 services for 1K users |
| Big tech behavioral | “We decided…” with no **I** |
| Startup HM | No questions about product or customers |
