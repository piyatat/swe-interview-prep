# Micron Technology engineering track

Sits beside [intel.md](intel.md) and [texas-instruments.md](texas-instruments.md): **memory and storage silicon + fab software** (DRAM, NAND, HBM, yield / SPC, tool automation), not a GPU-kernel house and not analog MCU firmware. Official [company](https://www.micron.com/about/company): vision *Accelerate intelligence to enrich life for all*; mission *Be a global leader in memory and storage solutions.* Recruiter confirms **firmware / drivers vs yield-data vs fab IT**, C++ vs Python vs SQL, Boise / US expansion sites / Asia, and intern vs experienced loop.

Typical path (official university FAQ): apply on [careers](https://careers.micron.com/) or campus → mix of **on-campus, phone, in-person, or virtual**; content is **technical + behavioral**. Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official process

Official [University recruiting](https://www.micron.com/about/careers/university-recruiting) resume + interview tips and FAQ.

| Stage | Official |
| --- | --- |
| Resume | Impact + keywords from the JD; early career: one page; measurable results |
| Formats | On-campus, phone, in-person, **often virtual** — test the tool, quiet space |
| Content | **Behavioral** (“tell me about a time”) **and** technical assessments by role |
| Technical | Coursework and **problem-solving**, not a published LeetCode catalog |
| Stories | Specific initiative / teamwork / debugging — generic answers fail |
| Close | Ask about team, growth, current projects (two-way) |
| Intern cycle | Applications **August–March** (most filled by end of January); intern term **May–August**; campus events September–March |
| Intern logistics | Paid; housing / transit options; re-apply after a no is allowed |

Reports (Dataford 2026): recruiter screen → technical phone → some loops a **project presentation** → onsite / virtual technical. DSA plus C / Python / SQL and semiconductor or embedded follow-ups. Treat extra OA and round **count** as **reported**. Pair: [../roles/embedded.md](../roles/embedded.md), [../roles/data-ml.md](../roles/data-ml.md), [../general/behavioral.md](../general/behavioral.md).

## How this track differs

| vs TI analog / MCU firmware | vs Lam / Applied tool software |
| --- | --- |
| Product is **DRAM / NAND / HBM + the software around it**, not analog signal chains | Software **for memory silicon and fabs**, not a deposition/etch OEM |
| Official six values + university interview FAQ | Yield, firmware, and data pipelines beat social-feed design |
| US fab / R&D expansion (Idaho, New York, Virginia) is context, not the pitch | C++ / Python / SQL mix — ask which desk |

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** memory house — a yield, firmware, or bandwidth constraint, not “HBM is in the news.”
2. C / bits: set a status flag; count set bits — [../answers/coding-number-of-1-bits.md](../answers/coding-number-of-1-bits.md).
3. Design a pipeline that flags a yield excursion from sensor / test logs — [../answers/system-design-metrics.md](../answers/system-design-metrics.md).
4. Values: a time you stayed on a hard debug (Tenacity) or partnered across process / software (Collaboration).
5. Questions: firmware vs yield-data vs IT, site, presentation vs live code, AI-in-pad.
