# Samsara engineering track

Sits beside [tesla.md](tesla.md), [rivian.md](rivian.md), and [datadog.md](datadog.md): **Connected Operations / physical-ops IoT + ingest**, not vehicle OEM firmware and not a generic observability loop. Official [Engineering & Product](https://www.samsara.com/company/careers/engineering-and-product): “Physical AI for the frontlines”; hardware they design plus cloud. Official [Culture Playbook](https://www.samsara.com/blog/the-samsara-culture-playbook): system of record for physical operations. Recruiter confirms **firmware / edge vs ingest vs maps / routing vs platform vs ML**, C/Go vs TypeScript, and OA vs live screen.

Typical timeline **~3–5 weeks** (2026 guides). OA: [../general/online-assessments.md](../general/online-assessments.md). Ingest cousin: [../answers/system-design-metrics.md](../answers/system-design-metrics.md). Embedded cousin: [../roles/embedded.md](../roles/embedded.md). ## Official hire bar (do not invent extra pillars)

Official playbook **values** (also on Staff SWE JDs). Map **your** stories.

| Official value | What they score |
| --- | --- |
| **Focus on customer success** | Ride-alongs, calls, outcomes — not tech for tech |
| **Build for the long term** | Enduring company; launch it right; sustained pace |
| **Adopt a growth mindset** | Curiosity, new challenges, lessons from misses |
| **Be inclusive** | Whole self; diverse frontline world they serve |
| **Win as a team** | Trust, respect, incremental value together |

Playbook also publishes **eight operating principles** (how, not a second value list). Score stories against the named ones: **sample the customer experience**, **work with urgency / deliver iteratively**, **work backwards from winning**, **keep a high bar**, **be intellectually honest**, **eliminate bureaucracy**, **solve problems together**, plus long-term **time/energy tradeoffs** (budget the team; hard decisions for later benefit).

“Why Samsara?” that only says “IoT / Tesla energy / I like hardware” fails. Name a **lossy link, edge model, or trillion-point ingest** problem you have lived.

## Official + reported process

Official [Emerging Talent](https://www.samsara.com/company/careers/emerging-talent) skeleton (intern / new-grad page; experienced loops are **not** a published stage list):

| Stage | Official / reported |
| --- | --- |
| Apply | Role-specific; rolling for early career |
| Skills evaluation (official) | Technical **or** non-technical assessment |
| Interviews (official) | Soft skills **and** technical expertise |
| Decision (official) | Written outcome from the team |

2026 Dataford / PracHub — treat as **reported**: recruiter → OA or tech screen → virtual onsite (coding + domain/system + behavioral). Guides: ~3 rounds, ~3–5 weeks. Confirm AI-in-pad; intern JDs say they want **AI-forward** builders, which is **not** a live-tool permit.

## How this track differs

| vs Tesla / Rivian / Datadog | vs FAANG web |
| --- | --- |
| Official **five values + playbook OPs**; B2B fleet / job-site | Design is **device → ingest → insight**, not “design Twitter” |
| Engineers visit trucks and sites (official How we work) | Heat / dust / vibration and intermittent radios show up |
| Full stack from rugged device to TS/React dashboard | “I only grind LeetCode” misses customer-success stories |

## Coding and design flavor

Official eng culture: C/Go on-device, protobufs, Kinesis-class ingest, Spark/Databricks offline, TS/React/React Native/GraphQL clients, edge DNNs under power/thermal caps. Live DSA often wears a geo / stream costume. Design: late GPS, camera backlog, multi-tenant org trees. Related: [../answers/system-design-object-storage.md](../answers/system-design-object-storage.md), [../general/system-design.md](../general/system-design.md).

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** physical-ops cloud — portable “I like IoT” is weak.
2. Live: window / heap / UF on sparse vehicle events; say the invariant first.
3. Design: dash-cam frames on a bad uplink — what you drop vs store vs retry.
4. Value: customer success — a time you changed the spec after a site visit.
5. Questions for them: firmware vs ingest vs ML, OA platform, AI-in-pad, site.
