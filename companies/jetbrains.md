# JetBrains engineering track

Sits beside [github.md](github.md) and [replit.md](replit.md): **developer-tooling house (IDEs, Kotlin, TeamCity, Space, Junie)**, not a git host or a browser-IDE loop. Official [Careers](https://www.jetbrains.com/careers/): **built by developers, for developers**; privately owned; **2.8K+** people, **15M+** customers. Recruiter confirms **IntelliJ platform / Kotlin / build-CI / cloud / Junie**, Kotlin vs Java vs research, and **EU hybrid site** (Germany, Czechia, Netherlands, Cyprus, …).

Typical timeline **~3–6 weeks** (official: CV review can take a few weeks). Take-homes: [../general/take-homes.md](../general/take-homes.md). Code review: [../general/code-review-rounds.md](../general/code-review-rounds.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official hire bar (do not invent extra pillars)

Official Careers **Who we hire** (six characteristics) + [Fit Test](https://blog.jetbrains.com/life-at-jetbrains/2026/05/the-jetbrains-fit-test-is-this-the-right-workplace-for-you/) (2026-05). Map **your** stories.

| Official signal | What they score |
| --- | --- |
| **Raise the bar** | Detail that lifted a standard, not “I shipped tickets” |
| **Care about the why** | Problem you chose because it mattered to users |
| **Don’t settle for good enough** | Path you found after “no” |
| **Lead from wherever you sit** | Decision without a title |
| **Independence + accountability** | Owned outcome when nobody watched |
| **Act with intent** | Impact over busyness |

“Why JetBrains?” that only says “I use IntelliJ / Copilot competitor” fails. Name a **language-tooling, inspect, PSI, build, or IDE-perf** problem you have lived. Official Fit Test: privately owned on purpose — do not pitch “IPO / growth-at-all-costs.”

## Official + reported process

Official [Careers](https://www.jetbrains.com/careers/) + [Engineering Hiring Process](https://blog.jetbrains.com/life-at-jetbrains/2026/07/jetbrains-engineering-hiring/) (2026-07). This is a **published** loop.

| Stage | Official |
| --- | --- |
| Application | CV + short cover letter (cover letter is a shortcut screen, not a save) |
| Recruiter | Last 2–3 roles: product, ownership, scale, stakeholders, **what you want next** |
| Team interview | 1–2 teammates + HM; live coding **or** case **or** code review. Recruiter warns if DSA is in scope |
| Test assignment | Realistic take-home for **most** roles; serious OSS / side project can replace it if the team agrees |
| Assignment review | Decisions, trade-offs, how you’d evolve it, **whether and how you used AI** |
| Final + references | Hard-skills hour; **three** workplace references; conflict-of-interest check; offer |

Official hiring guide: strongest candidates **follow the spec**. Extra “spaceship” features do not rescue missed requirements. Clean, readable code beats overengineering.

## How this track differs

| vs GitHub / Replit | vs FAANG web |
| --- | --- |
| Official **take-home + AI-usage review** | Design is **IDE / compiler / inspect**, not a social feed |
| Private company; doer-led, flat | Puzzle DSA only if recruiter **warned** you |
| Hybrid EU offices, not SF HQ-first | References are a **real gate**, not a formality |

## Coding and design flavor

Practical Kotlin / Java / C++: PSI / indexes, incremental compile, inspect, plugin APIs. Related: [../general/low-level-design.md](../general/low-level-design.md), [../answers/system-design-collab-editor.md](../answers/system-design-collab-editor.md). Bring a **repo they can open**.

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** tooling company — a time you dogfooded a painful editor / compiler path.
2. Trait: raise the bar — a standard you set that others adopted.
3. Live: small case or review; narrate trade-offs, not a memorized Hard.
4. Take-home debrief: what you cut, how you used AI, what you would change in week two.
5. Questions for them: platform vs Kotlin vs Junie, take-home vs OSS swap, site / hybrid.
