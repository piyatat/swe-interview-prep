# G-Research engineering track

Sits beside [quant.md](quant.md) and [jane-street.md](jane-street.md): **London quantitative research + technology** (Soho Place), not Jane Street’s official open-ended pair and not Citadel Securities’ one-problem day. Official [About](https://www.gresearch.com/about/about-us/): scientific rigor + ML + platforms to **predict markets**. Recruiter confirms **SWE vs research engineer vs ML vs infra**, **QP vs Core vs Trade Technology**, C++ / C# / Python, visa / relocation, and whether you get the **at-home task**.

Typical path: application → technical (or remote test) → behavioural → deeper technical → management (official engineering page). QP blog is more specific. Design: [../general/low-level-design.md](../general/low-level-design.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official culture (themes, not invented LPs)

G-Research does **not** publish a numbered LP table. Use the official [About](https://www.gresearch.com/about/about-us/) + [Life](https://www.gresearch.com/careers/life-at-g-research/) language. Map **your** stories.

| Official theme | Careers one-liner |
| --- | --- |
| **Honesty** | Culture “built on honesty, curiosity and a long-term perspective” |
| **Curiosity / deep exploration** | Best ideas take time; methodical execution |
| **Long-term thinking** | Win over time, not a quarter-only slogan |
| **Collaboration** | Researchers and engineers generous with time and ideas |
| **People, not code monkeys** | Official engineer quote they chose to publish — treat it as a bar |

“Why G-Research?” that only says “quant comp / London” fails. Name a **research-platform, batch compute, or correctness-under-load** problem you have lived. Confirm you are interviewing as a **Developer**, not a Quantitative Analyst — official QP phone call exists to stop that mix-up.

## Official process — Quant Platform (blog)

Official [What to expect from a Quant Platform Software Engineering interview](https://www.gresearch.com/news/what-to-expect-from-a-quant-platform-software-engineering-interview-updated/) (updated write-up of the QP loop). **Ask** if your req uses this or the shorter careers ladder.

| Stage | Official QP |
| --- | --- |
| Phone (~15 min) | What G-Research does; QP vs quant analyst; role shape |
| At-home task | Preferred language + IDE; **best work**, not memory-SQL. On-site alternative if you cannot do homework |
| On-site technical (half day) | Three structured interviews from a **shared question list** |
| Homework review | Walk the take-home as a **code review** |
| Design | Changing requirements; assumptions; communicate decisions — **not** trivia about a known system |
| Algorithms | Hard problems + **hints and extensions**; complexity of basic structures |
| Managers (second half-day) | Line manager + group head; technical background; career fit |
| Meet the team | Informal; they have picked a QP team |

Official: two half-days or one full day; international candidates may stay remote. They dropped pen-and-paper office tests on purpose.

## How this track differs

| vs Jane Street / HRT | vs generic FAANG |
| --- | --- |
| Official **homework + review**, then design, then algo | Design scores **assumption-change**, not a social feed |
| London research firm; SWE builds the **research platform** | Behavioural is a **named stage**, not a five-minute closer |
| Shared question list + hints (fairness) | “I only grind Blind 75” misses maintainable-code review |

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** research platform — compute / data / correctness, not “I like trading.”
2. Take-home: production README, tests, what you would cut; then **defend** it like a PR.
3. Design: respond when the SLO or data volume moves; say what you do **not** know.
4. Algo: take the hint; extend; name Big-O of the structure you picked.
5. Questions: QP vs other eng, C++ lock, homework vs on-site task, AI-on-task.
