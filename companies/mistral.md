# Mistral AI engineering track

Sits beside [ai-labs.md](ai-labs.md) and [hugging-face.md](hugging-face.md): **independent frontier lab (open-weight models + products)**, not a closed US lab loop and not a Hub-only platform. Official [Careers](https://mistral.ai/careers/): mission is to **make frontier AI open to all**; **900+** people, Paris-centered with other sites. Recruiter confirms **science vs product/eng vs infra**, Python / Go, Paris / London / Palo Alto / other, and visa.

Typical timeline **~3–6 weeks** (official skeleton + 2026 JDs). LLM serving: [../answers/system-design-llm-serving.md](../answers/system-design-llm-serving.md). AI rounds: [../general/ai-assisted-rounds.md](../general/ai-assisted-rounds.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official hire bar (do not invent extra pillars)

Official [Careers](https://mistral.ai/careers/) values + “Interviewing with us.” Map **your** stories. Do **not** paste Amazon LPs.

| Official signal | What they score |
| --- | --- |
| **Audacity** | A new approach you actually tried, not a slogan about AGI |
| **Rigor** | Data that changed the call — they score **analytical**, not vibe |
| **Customer centricity** | Customer success as the eval, not a prettier demo |
| **Speed** | Experiment → detect the miss early → ship the fix |
| **Low-ego** | Hands dirty outside your lane; company outcome over credit |
| **Raise the bar** (interviewing) | System improver who challenges thinking — not a people-pleaser |
| **Builders, not order takers** | Own the problem even when you did not create it |
| **Directness** | Content over tone; give and take critical feedback |

“Why Mistral?” that only says “OpenAI but European / open” fails. Name a **serving, eval, open-weight deploy, or product** problem you have lived.

## Official + reported process

Official Careers: science / product / engineering = intro → **2–5 technical exercises** that reflect real work → **values conversation**. **Reference checks always** before offer. Apply via the official [Ashby board](https://jobs.ashbyhq.com/mistral.ai). Role JDs sometimes list a finer split — treat those as **role-specific**, not a second company process.

| Stage | Official / reported |
| --- | --- |
| Intro (~30–45) | Recruiter or HM: experience, interests, location |
| Technical (typically 2–5) | Official: exercises like the job. JDs (reported): live coding, system design, deep-dive for leads |
| Values | Alignment with the five values + ways of working |
| References | Official: always, before the offer |
| Offer | Level, site, visa; Paris vs US satellite is not the same listing |

New-grad JDs (2026, reported): OA (~60) + intro + live coding + HM + deep dive + culture. Backend JDs add a 45-min design hour. Confirm AI-in-pad; do not assume a lab work-trial like OpenAI.

## How this track differs

| vs OpenAI / Anthropic | vs Hugging Face |
| --- | --- |
| Official **five values + 2–5 real exercises + references** | They **train frontier models** and ship platforms, not only Hub tooling |
| Open-weight mission is on Careers | Design is **inference / eval / deploy**, still a lab bar |
| Paris-centered independent lab | “Why open” must be a **product** story, not a license rant |

## Coding and design flavor

DSA in a **systems costume**: graphs, heaps, concurrency. Design: batch vs stream decode, KV cache, multi-tenant API, eval harness. Related: [../roles/data-ml.md](../roles/data-ml.md). Talk **correctness and cost**, not parameter counts.

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** independent lab — a time open weights (or not) changed a customer outcome.
2. Value: rigor — a metric that killed a “cool” model change.
3. Live: medium coding; narrate tests before cleverness.
4. Design: an inference API that survives a noisy neighbor tenant.
5. Questions for them: science vs product/eng, how many exercises, AI-in-pad, site.
