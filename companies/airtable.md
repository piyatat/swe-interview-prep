# Airtable engineering track

Sits beside [notion.md](notion.md), [monday.md](monday.md), and [retool.md](retool.md): **flexible-schema bases / interfaces / AI apps**, not a docs canvas, not a Work OS board, not an internal-tools IDE. Official [Careers](https://airtable.com/careers): “empower anyone to create AI-powered apps”; hybrid hubs **SF, Austin, NYC, London** (select Seattle / LA remote). Recruiter confirms **product vs infra vs storage vs AI**, and **take-home vs live screen** (official fork).

Typical timeline **3–4 weeks** (official FAQ; some 2026 reports run longer). Take-homes: [../general/take-homes.md](../general/take-homes.md). Review: [../general/code-review-rounds.md](../general/code-review-rounds.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official hire bar (do not invent extra pillars)

Official Careers culture lines + FAQ. Map **your** stories. Do not invent FAANG LPs.

| Official signal | What they score |
| --- | --- |
| **Builders / work in the product** | You actually use (or would build) bases; dogfooding, not slideware |
| **AI is integrated, not an afterthought** | A real workflow where AI earned its keep |
| **Learn by doing** | High-context goal → you chose the strategy and took feedback fast |
| **Share the “why”** | Others could rebuild your decision from the write-up |
| **Mission** | Software **by** the customer, not only **for** them |

Official FAQ **AI in interviews**: AI is fine for **prep** (organize thoughts, practice). **Do not** use AI tools **during the actual interview**. They want how you already use AI at work — most roles expect **AI fluency**. Confirm the live-pad rule the week you interview.

“Why Airtable?” that only says “spreadsheets with views / I hate Jira” fails. Name a **formula graph, sync, permissions, or interface** problem you have lived.

## Official + reported process

Official Careers FAQ is the skeleton. Older [eng post](https://medium.com/airtable-eng/diversity-and-inclusion-in-product-development-at-airtable-e82126452f0f): first technical phase is **live phone or take-home**, take-home reviewed **blind**. 2026 TechPrep extras — treat as **reported**.

| Stage | Official / reported |
| --- | --- |
| Recruiter screen | Official: experience, interests, goals |
| Hiring manager | Official: role, team, what success looks like |
| Practical evaluation | Official: take-home **or** technical screen **or** portfolio |
| Panel (virtual) | Official: teammates + cross-functional partners |
| References | Official: before offer |
| Reported extras | HackerRank OA (2–3 easy/medium), CodePair or **PR review** (~120–150 lines), two coding + design + product/behavioral, hiring committee |

Do not assume a 6–8 hour unpaid project unless the recruiter assigns it. If they do, write code you can **walk line by line**.

## Coding and design flavor

Official product: bases, interfaces, automations, AI apps. Live work: cell formula DAGs (topo / cycles), real-time sync, undo/redo, field types, ACL. Related: [../answers/coding-course-schedule.md](../answers/coding-course-schedule.md), [../answers/system-design-collab-editor.md](../answers/system-design-collab-editor.md).

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** builder platform — portable “no-code is hot” is weak.
2. Culture: Share the why — a decision others could replay from the doc.
3. Coding: evaluation order for spreadsheet formulas; detect a cycle.
4. Review: 150 lines; SRP, exceptions, what you would not change in 45 min.
5. Design: real-time sync for a 100k-row base; who owns the formula graph.
6. Questions for them: take-home vs pad, PR-review language, AI-in-pad vs FAQ, hub days.
