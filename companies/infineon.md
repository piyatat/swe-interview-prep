# Infineon Technologies engineering track

Sits beside [nxp.md](nxp.md) and [texas-instruments.md](texas-instruments.md): **power systems + automotive / IoT silicon and the firmware that ships on it** — not an MCU-only NXP loop and not a TI analog-lab hour. Official [Company](https://www.infineon.com/cms/en/about-infineon/company/): *We make life easier, safer, and greener*; leader in **power systems** (Si / SiC / GaN) and **smart, secure IoT**. Recruiter confirms **AURIX / auto firmware vs power-conversion vs security IC vs cloud/edge platform**, C vs C++, Munich / Augsburg / Austin / other sites, and intern vs experienced loop.

Typical path **~3–5 weeks**, four reported stages (Dataford, updated 2026-11). Embedded: [../roles/embedded.md](../roles/embedded.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official culture (purpose, not LPs)

Do **not** invent Amazon LPs. Infineon does **not** publish a five-word leadership-principle list on careers. Use official language, then map **your** stories.

| Official note | What they score |
| --- | --- |
| **Easier, safer, greener** (company) | Energy, mobility, or secure IoT you actually touched |
| **#WeAreIn** (careers) | Decarbonization + digitalization — not “I like chips” |
| **Jobs that matter** | A tiny part with a named customer outcome |
| **Open-door / belonging** | Cross-site, hardware + software; managers approachable |
| **Four career paths** | IC, management, project management, **technical ladder** — which desk |

Official [Software Engineers](https://www.infineon.com/careers/teams/software-engineers) page is **cloud platform and edge / customer systems**, not only register-level C. Ask which.

“Why Infineon?” that only says “Germany / auto chips” fails. Name a **driver, ISR, power-stage, or secure-boot** problem you have lived.

## Official + reported process

Careers site is the apply door; no public numbered SWE stage list. Dataford (updated 2026-11-06) — treat round *count* as **reported**.

| Stage | Official / reported |
| --- | --- |
| Apply | [Careers](https://www.infineon.com/careers); campus OA on some pipelines |
| Phone / video | Talent acquisition or HM: stack, site, authorization |
| Technical (1–3) | Live coding, OOP, project deep-dive; embedded C / RTOS / protocols on silicon desks |
| Project presentation | Short deck + Q&A with seniors on many experienced loops |
| Close | Cultural fit / manager; consensus hire |

Interview flavor (reported): `volatile`, stack vs heap, bit masks on registers, SPI / I2C / UART, RTOS priority inversion — [../roles/embedded.md](../roles/embedded.md). Cloud / platform desks add APIs and pipelines. Pair: [../general/behavioral.md](../general/behavioral.md).

## How this track differs

| vs NXP / TI | vs FAANG |
| --- | --- |
| Product is **power + auto MCU + secure IoT**, not phone SoCs or converter-only analog | Design is **firmware / safety / energy**, not “design Twitter” |
| Official **purpose + four career paths**, no LP quiz | C on a constrained node more than Blind-75 bingo |
| Firmware **and** Infineon Cloud / edge software exist | Confirm AURIX vs power vs security vs platform |

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** power / auto house — a driver, boot, or efficiency constraint, not “I like cars.”
2. C: `volatile` on an ISR flag; stack vs heap vs BSS — [../roles/embedded.md](../roles/embedded.md).
3. SPI vs I2C vs UART: lines, duplex, who is clock master.
4. Purpose: easier **or** safer **or** greener on the same incident.
5. Questions: firmware vs cloud/edge, C vs C++, OA vs live, AI-in-pad.
