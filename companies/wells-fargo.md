# Wells Fargo engineering track

Sits beside [citi.md](citi.md) and [jpmorgan.md](jpmorgan.md): **U.S. consumer / commercial-bank technology** (deposits, cards, wholesale, risk) — not a Super Day cohort hire and not “the same Java shop as Citi.” Official [Culture](https://www.wellsfargojobs.com/en/life-at-wells-fargo/culture/): **Company Expectations** for every role. Recruiter confirms **CIO vs line-of-business**, Java vs other stack, Charlotte / Dallas / Phoenix / other hub, and live AI.

Typical timeline **a few weeks** (Glassdoor / TechPrep). Coding: [../general/coding-patterns.md](../general/coding-patterns.md). SQL: [../general/sql-interviews.md](../general/sql-interviews.md). ## Official culture (Company Expectations)

Do **not** recite Amazon LPs. Official [Culture](https://www.wellsfargojobs.com/en/life-at-wells-fargo/culture/): six Expectations. Map **your** stories.

| Official line | What they score |
| --- | --- |
| **Embrace candor** | Direct, respectful disagreement — not “we all got along” |
| **Do what’s right** | You named a customer / control problem and made it right |
| **Be great at execution** | Goal, date, quality, simpler process, lower control risk |
| **Learn and grow** | Feedback you asked for; obstacle you did not quit on |
| **Champion inclusion** | Someone else could speak; you made room |
| **Build high-performing teams** | Managers only: hire, vision, accountability, risk mindset |

Official [hiring process](https://www.wellsfargojobs.com/en/life-at-wells-fargo/our-hiring-process/): apply → recruiter / HM review → interviews **vary by business group** (phone, group, or 1:1). “Why Wells Fargo?” that only says “bank / Charlotte” fails. Name a **controls, execution, or customer-journey** problem.

## Official + reported process

Official behavioral prep uses **SBO** (situation, behavior, outcome) — they say it **replaced STAR**. Keep task implicit; lead with what **you** did and the result.

| Stage | Official / reported |
| --- | --- |
| Apply | [wellsfargojobs.com](https://www.wellsfargojobs.com/en/life-at-wells-fargo/our-hiring-process/) — Autofill with Resume |
| Review | Recruiter or hiring manager |
| OA (guides) | TechPrep (2026): proctored HackerRank 60–90 min; **no backtracking**; MCQ + GenAI concepts + 2–3 coding |
| Tech | 1–2 × 45–60 min: resume + Java / DSA / SQL; second often a **panel** |
| HM / behavioral | 30–45 min; SBO vs Expectations |
| Campus | Engineering Associate / intern: often a **Superday** of 2–3 back-to-back |

[../general/ai-assisted-rounds.md](../general/ai-assisted-rounds.md): **ask**. OA GenAI MCQs ≠ permission to paste a model into the live hour.

## How this track differs

| vs Citi | vs FAANG |
| --- | --- |
| Official **SBO**, not STAR; six Expectations, not three LPs | Easy–medium DSA + **Java + SQL**, not olympiad graphs |
| OA is reported **HackerRank**, not Karat | Design is **payments / controls**, with risk in the first sketch |
| Loop **varies by group**; campus Superday is the consolidation | Background / onboarding after the verbal |

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** Wells Fargo tech org — Do what’s right when a control and a launch date disagreed.
2. Easy–medium: prefix / hashmap / stack; then a SQL join + `GROUP BY`.
3. Java: overloading vs overriding; `final` / `finally`; REST vs SOAP if the JD is services.
4. Design: retry-safe posting or Nth-highest-salary-style reporting on a large table.
5. SBO: candor in a meeting that was going to ship a wrong number.
