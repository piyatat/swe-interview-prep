# Gusto engineering track

Sits beside [rippling.md](rippling.md), [workday.md](workday.md), and [intuit.md](intuit.md): **SMB payroll + benefits + compliance**, not a compound HRIS/IT platform and not enterprise HCM or consumer tax. Official [Careers](https://gusto.com/about/careers): “grow the small business economy with technology and heart”; payroll/benefits/compliance are edge cases with **real paychecks**. Recruiter confirms **payroll/tax vs benefits vs platform vs frontend**, Ruby vs TypeScript, and CodeSignal vs live screen.

Typical timeline **~3–5 weeks** (2026 guides). OA: [../general/online-assessments.md](../general/online-assessments.md). Ledger cousin: [../answers/system-design-payment.md](../answers/system-design-payment.md). Comp: [../general/offer-negotiation.md](../general/offer-negotiation.md).

## Official hire bar (do not invent extra pillars)

Official [About](https://gusto.com/about) / [Careers](https://gusto.com/about/careers) list **four** current values. Map **your** stories. (Older posts named a different six — use **these**.)

| Official value | What they score |
| --- | --- |
| **Customer Obsessed** | Underserved SMBs; you changed the spec after a real payroll pain |
| **Raise the Bar, Learn Fast, Repeat** | Tight loops, hypotheses, excellence; AI as leverage, not a slogan |
| **Dream Big, then Make it Real** | Ambition **plus** end-to-end ownership; step outside the lane |
| **Act with Bold Conviction** | Make the two-way-door call; course-correct without waiting for consensus |

Careers also: **directness, healthy debate, clear decisions**; most hub roles are in-office **two days/week** (SF/NYC/Denver Tue–Wed). Official AI line: accuracy and trust because **real paychecks**. Engineering [bar](https://engineering.gusto.com/code-schools-the-bar-3ef6dc5dc73a): CS fundamentals + coding + collaboration — same bar regardless of pedigree.

“Why Gusto?” that only says “HR tech / I like payroll” fails. Name a **tax jurisdiction, benefits eligibility, or money-movement** problem you have lived.

## Official + reported process

Gusto does **not** publish a numbered SWE stage list. 2026 Dataford / FinalRound — treat as **reported**:

| Stage | Official / reported |
| --- | --- |
| Recruiter screen | Fit, level, hub (SF, NYC, Denver, Scottsdale), authorization |
| Technical assessment | CodeSignal **or** ~60-min live screen (guides) |
| Final loop / “super day” | Pair coding, architecture, hiring manager (guides) |
| Values & Motivations (VMA) | Dedicated values hour — unique to this loop (guides) |

Guides: ~3–5 weeks; offer often within ~5 business days after the last session. Confirm AI-in-pad; official careers talk about **building** AI for customers, which is **not** a live-tool permit.

## How this track differs

| vs Rippling / Workday / Intuit | vs FAANG web |
| --- | --- |
| Official **four values** + reported **VMA** hour | Design is **payroll correctness**, not “design Twitter” |
| SMB + US tax/benefits maze, often Rails + services | “I only grind LeetCode” misses customer-obsessed stories |
| Money that must be **right** on payday | Ask AI-in-pad; do not assume an AI hour |

## Coding and design flavor

Guides: practical parse / money split / tax brackets / time-based KV more than puzzle DSA. Design: scheduling, partner-bank / tax APIs, idempotent payouts. Related: [../answers/coding-time-based-kv.md](../answers/coding-time-based-kv.md), [../general/low-level-design.md](../general/low-level-design.md).

## Sample prompts (shapes, not leaked puzzles)

1. Why **this** SMB payroll platform — portable “fintech / HR” is weak.
2. Live: split a payout across capped recipients, or implement historical `get`.
3. Design: run payroll across states — withholdings, retries, a failed ACH.
4. Value: Act with Bold Conviction — a two-way door you took without a committee.
5. Questions for them: CodeSignal vs live, VMA format, hub days, AI-in-pad.
